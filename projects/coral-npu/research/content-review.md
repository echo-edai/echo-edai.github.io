## 人工核查重点

### 参数默认值与实际目标

`Parameters.scala` 的 ITCM/DTCM 默认大小为 8/32 KiB，highmem 为各 1024 KiB；`rvvVlen` 为 128，`instructionLanes` 为 4，`fetchDataBits` 和 `lsuDataBits` 为 256。`enableRvv`、`enableVme` 等基类默认值不等于每个生成目标的启用配置。必须沿 `Core.scala` 的参数覆盖、构建目标和 wrapper 实例路径确认。

`CoreAxi.scala` 当前显式实例化 `TCM128`、`SRAM`、`FabricArbiter`、`FabricMux` 等单元。仓库里存在 `BankedDtcm` 文件不能证明它在这一实例路径中工作。语法依赖图也不能替代对某个特定配置的完整展开。

### NoC、缓存一致性与目录

当前课程必须保持以下区分：

1. 本地 Fabric/地址分流与路由器网络分别讨论，不能把一个 mux 和 arbiter 直接画成 mesh NoC。
2. 紧耦合内存 TCM 的显式地址与访问仲裁，不等于带标签和替换策略的通用 Cache 层级。
3. Runtime 的只读 binding cache 只是避免重复搬运数据，不提供硬件多核一致性。
4. LSU 对未完成读事务和返回数据的监测，不等于 directory controller 的 owner/sharers 权限管理。
5. NoC 搬运消息，一致性协议管理权限和可见性；设计一个网络不能自动得到缓存一致性。
6. 两核单行教学目录仅用于学习瞬态、探针和 ACK；不覆盖所有真实多行缓存、并发、替换、回写、互连顺序与死锁条件。

### Pin 与补丁共同定义软件栈

主硬件快照 `f795221…` 与编译器 submodule 固定硬件 `782675a…` 不同。编译器 `d715556…` 还锁定 IREE、LLVM、Coral MPACT 与 MPACT RISC-V，并应用补丁。复现实验时必须记录两者。

原始 Coral MPACT 固定快照的 `hw_sim` 包装使用 M3 decoder/V2 state。编译器的 `coralnpu-mpact-0001-vme-m4-decoder.patch` 才将这个包装接到 M4/Zvt，并补充编码、状态和 BF16 指令。因此“仓库含 M4 文件”与“实际链接的模型启用了 M4”要分别确认。

`mpact-riscv-0003` 调整 BF16 altfmt，`0004` 调整 round-to-odd 和精确和残差处理。未打补丁的模型不能自然视为编译器集成模型。此次仅阅读源码和补丁，未编译或执行该集成模型。

### 编译器与数值

`vector.contract` 不是最终 Zvt 指令的证据；需检查目标特征、类型/形状合法性、容量、后续 Pass 与最终汇编。Host 回退、RVV 回退与编译错误是不同结果。

文档中的卷积 IGEMM affinity 限制不能推广为所有卷积路径不支持 Zvt，直接 spatial convolution 需要单独看。Tiling 文档的 8 KiB DTCM 例子也不能覆盖硬件当前 32 KiB 默认值。

输入类型、累加宽度、输出类型、舍入、浮点重排、NaN/Inf 与溢出都属于数值合同。更高宿主精度并不必然与分组舍入的目标硬件位精确相同。

### 运行时与验证

同步 inline one-shot HAL 的 barrier 空实现依赖同步执行前提。将该设计改为异步 DMA、并发队列或多核后，必须重新实现完成、可见性和同步合同。

MPACT/Spike 的功能证据、Verilator 针对选定 RTL 构建的证据、FPGA 板级证据分别说明。模型计数器不能直接作为硅性能。上游 README 的性能数字和 cost-model 常数没有被写成此次实测。
